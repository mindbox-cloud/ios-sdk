Сейчас кэш WebView в SDK выключен (.nonPersistent()) → каждый показ качает всё заново: byendpoint 826 КБ + картинки ~2.9 МБ. Три рычага это убирают.

Замерено — два инаппа подряд в одной сессии

Показкак сейчассо стекомбыстрее

Медианы, симулятор. Показ №2 быстрее №1, хотя онбординг тяжелее — переиспользованный «тёплый» WebView уже показывал контент.

Как это работает — три рычага (все в SDK)

  • 1
    Персистентный кэш. .nonPersistent() → .default(): ресурсы кэшируются по заголовкам CDN и переживают перезапуск. → повторный показ ~3–4×.
  • 2
    Прогрев + переиспользование. Один тёплый WKWebView на старте, одалживается каждому показу (не уничтожается). → убирает ~530 мс спин-апа с каждого показа.
  • 3
    Cacher. На прогреве тянет общий рантайм (tracker + byendpoint) в кэш → первый показ за них уже не платит.

Что нужно решить

приватность

Идём в персистентный кэш?

.default() персистит и cookies/localStorage — нужен разбор приватности. Главный рычаг.

iOS

Какой стор

.default() (просто) vs iOS 17+ изолированный forIdentifier (чище по приватности).

бэкенд

Стабильный URL byendpoint

Сейчас кэш-бастинг каждые 5 мин → перекачка. Стабильный URL от бэка → кэшируется всегда.

android

Включить кэш на Android

Гипотеза LOAD_NO_CACHE → LOAD_DEFAULT. Не проверяли — нет окружения.

План — фазами

Фаза 1Кэш + reuse — чистый SDK, даёт основной выигрыш. Риск: разбор приватности .default().
Фаза 2Cacher грузит реальный index.html без formId (актуальные версии). Чистый SDK.
Фаза 3Серверный cacher + префетч статичных картинок форм. Опц., нужен фронт/бэк.

Статус и честные оговорки

  • Работает на реальном устройстве — стек ощущается вживую, не только в замерах.
  • Открытый инж-вопрос: где поднимать прогрев. Создание первого WKWebView стоит ~100 мс main-потока — это переносится со «первого показа» на «старт», не новая цена. Нужен профиль на устройстве (регрессия time-to-first-frame) → решаем место.
  • Прогреву нужна фора: если показ почти сразу за стартом, кэш ещё не докачан — не поможет.
  • Перед шипом: убрать прототипный тумблер/метки; кэш best-effort (вытесняется), офлайн не цель.
