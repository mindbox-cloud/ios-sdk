# Решение: WebView-кэш — `.nonPersistent()` → `.default()` (+ prewarm/reuse + cacher)

Ускорение показа WebView-инаппа. Прототип на ветке `prototype/webview-cache-profiling`, замерен
на двух инаппах (стирашка ~3МБ, онбординг). Детали: `webview-show-profile.md`, `webview-cache-overview.md`.

## Проблема

Показ WebView-инаппа медленный: холодный полный показ ~2.3–3.4 с. Раскладка узкого места:
- **~530 мс** — спин-ап web-content процесса WebKit при первом `loadHTMLString` (в каждом показе);
- **загрузка контента** — byendpoint 826 КБ + tracker/main + картинки 2.9 МБ качаются по сети;
- сейчас в SDK `websiteDataStore = .nonPersistent()` → **кэш выключен**, каждый показ качает всё заново.

## Решение (три независимых рычага)

1. **Персистентный кэш.** `websiteDataStore` с `.nonPersistent()` → `.default()` (iOS 17+ — изолированный
   `WKWebsiteDataStore(forIdentifier:)`). Ресурсы кэшируются по заголовкам CDN (картинки 7 дней, tracker/шрифты
   1 день, byendpoint 5 мин) и переживают перезапуск. → повторный показ ~2.3–3.4 с → **~0.8 с**.
2. **Прогрев + переиспользование инстанса.** Один сессионный тёплый `WKWebView` создаётся на старте
   in-app подсистемы; **одалживается** каждому показу и на закрытии **скрывается, а не уничтожается**
   (borrow-not-consume). → убирает спин-ап (~530 мс) и создание WebView; показ №1 быстрый, №2/№3 ещё быстрее.
3. **Cacher.** На прогреве грузим локальную страничку, которая подтягивает общий рантайм (tracker.js +
   main.js + шрифты + **byendpoint 826 КБ**) в персистентный кэш. → первый холодный показ не платит за них.

**Стек вместе: полный показ ~3.4 с → ~0.4 с** (navStart ~620→~61 мс, byendpoint 345→3 мс).

## Как реализовано (прототип, за launch-флагами)

| Рычаг | Где | Как |
|---|---|---|
| Персистентный стор | `MindboxWebViewFacade.init` | `config.websiteDataStore = usesPersistentStore ? .default() : .nonPersistent()` (флаг `-MBWVPersistentStore`) |
| Прогрев/reuse | `WebViewShowProfiler.prewarmIfRequested()` из `InAppCoreManager.start()` | создаёт тёплый `WKWebView`, грузит cacher, держит ссылку; `borrowWarmWebView()` отдаёт его показу не обнуляя (флаг `-MBWVReuseInstance`) |
| Cacher | `WebViewShowProfiler.cacherHTML` | хардкод HTML-строкой в Swift, `loadHTMLString`; `<script>` на tracker/main/byendpoint + `<link>` шрифты |
| Идемпотентный мост | `MindboxWebBridge.init` | `removeScriptMessageHandler` перед `add` — чтобы reuse не дублировал хэндлер |

Профайлер (`WebViewShowProfiler`) и флаги — **выкидные, измерительные**; в проде удаляются.

## Что нужно доработать до прода

- **Стор:** iOS 17+ изолированный `forIdentifier` (ниже — `.default()`); **разбор приватности** — `.default()`
  персистит и cookies/localStorage, а не только кэш.
- **Cacher грузит настоящий `index.html`, а не хардкод версий.** index.html всегда актуален и диктует `?v=`
  для tracker/main; хардкод `?v=1.0.29` после бампа версии греет неактуальное (безопасно, но бесполезно).
  endpoint брать из конфига, не хардкодить `mpush-test.webview`.
- **Reuse-жизненный цикл:** держать один сессионный инстанс, ре-прогревать после показа; следить за памятью;
  тот же стор, что у показа.
- **Управление размером кэша:** байтовый лимит задать нельзя и размер не прочитать (см. overview §6) →
  политика `removeData(ofTypes:modifiedSince:)` по дате или снос изолированного стора; на «всегда в кэше»
  не полагаться (best-effort).
- Убрать профайлер + флаги; тесты.

## Нужен ли серверный файл для prewarming?

Не обязательно. Два пути:

- **Без нового файла (проще):** на прогреве грузим **существующий `index.html` без formId** (тот же
  bootstrap, что у показа). Рантайм инициализируется, тянет tracker + byendpoint (актуальные версии,
  сам вычисляет кэш-бастинг) → кэш прогрет, форма не рендерится (нет formId → нет показа). Бэкенд не трогаем.
- **С серверным cacher-файлом (мощнее):** бэкенд отдаёт отдельный `cacher.html` — он знает текущие версии,
  может **предзагружать статичные картинки форм** (URL берутся из byendpoint) и вообще курировать, что греть.
  Требует работы фронта/бэка, но даёт контроль и покрывает картинки.

**Картинки:** статичные картинки форм префетчиваемы (их URL зашиты в byendpoint.js) — но для этого нужен
либо серверный cacher, который их перечислит, либо парс byendpoint на клиенте. Рекомендательные картинки
(per-user, рантайм) заранее не подкачать.

**Рекомендация:** минимальный шип — `.default()` + прогрев через реальный `index.html` без formId (без
бэкенда). Расширение — серверный cacher-файл для префетча статичных картинок.

## Риски / ограничения

- Приватность `.default()` (cookies/localStorage персистятся) — нужен разбор.
- Кэш best-effort: вытесняется (LRU-подобно, по давлению ёмкости), офлайн не гарантирован.
- byendpoint кэшируется только в пределах 5-мин окна кэш-бастинга (правильно лечится стабильным URL на бэке).
- Reuse держит `WKWebView` живым всю сессию — память (один инстанс, приемлемо).

## Результаты (замерено, медианы)

| | как сейчас | стек (кэш + reuse + cacher) |
|---|--:|--:|
| Полный показ (стирашка ~3МБ) | ~3.4 с | **~0.4 с** |
| Полный показ (онбординг) | ~2.3 с | **~0.4 с** |
| navStart (создание+спин-ап) | ~620 мс | **~61 мс** |
| byendpoint (826 КБ) | ~345 мс | **~3 мс** (из кэша) |
